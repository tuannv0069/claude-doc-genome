# Recognizing a procedure that could become a capability

## §1 Establish a real workflow

A packaging candidate needs a recognizable trigger, dependent operations and a defined output. A glossary, evidence policy or checklist may be useful without being a repeatable procedure. Do not create a skill merely because a guide is long or has numbered items.

## §2 Notice candidates during authorized work

When following a guide with those workflow properties, inspect installed skills and agents for an existing owner. If none exists, retain the guide's identity as a candidate while completing the user's task. Raise a useful optional candidate afterward; do not interrupt the task to build an unrequested capability.

Check recorded rejections before repeating a proposal. No extra execution registry is needed just to recognize the procedure already being used.

## §3 Keep discovery sweeps within their request

Perform a broad search for recurring unowned procedures only when requested. Use task records, lessons and history to identify repeated actions, then establish their actual trigger, steps and output. Several independent instances are evidence of recurrence, not proof that all instances share a stable procedure.

## §4 Choose and authorize the form

A skill suits a repeatable sequence in one context. A separate agent suits work that needs independent context. A single criterion remains a guide requirement when it does not define a workflow. A skill may include an independent review without becoming a universal multi-agent requirement.

Explain the practical benefit and proposed owner when making an optional proposal. Creation needs the user's request or existing delegated authority, which does not need reconfirmation. Use `.agent-workspace/rules/skill-md-standards.md` §1 or `.agent-workspace/rules/codex-agents-standards.md` §1 when implementing the authorized capability.

## §5 Retain the reason for a declined proposal

Record a rejection when its reasoning cannot be reconstructed later, under `decision-journal.md` §1. Capture a repeatable proposal-method failure under `lesson-capture.md` §2 when applicable. Reconsider only when new evidence addresses the earlier reason.
